# 读书姬 2.1

> 一个活字乱刷术的tts程序和hanser的公开音频制成的音库（不全）和我自己写的池沼恋爱小说（喜）

用二次元语音包朗读中文 TXT。Windows 桌面程序，纯离线。

```
python -m voice_reader          # 启动图形界面
python -m voice_reader --check  # 资源自检（不开界面，退出码表示结果）
python -m voice_reader --render <txt> <out.wav>   # 渲染"实际会送进声卡"的音频
python SearchTool.py -p 椎名樱   # 速查拼音与录音
python tools/build_voicepack.py hanser   # 离线补齐语音包
python tools/check_all.py       # 一条命令跑完全部体检（11 项）
python tools/build_exe.py --test        # 打包成单文件 exe 并冒烟测试
python tools/build_phoneme.py hanser     # 生成音素级补齐层（实验，可回滚）
```

## 打包成 exe

```
python tools/build_exe.py --test
```

产出 `dist/读书姬.exe`（约 50MB，单文件，目标机器**无需装 Python**）。
资源（语音包 / WTV.data / 读音表）整包打进去。

打包时的三个坑（都已在 `voice_reader.spec` 里处理）：

1. **`datas` 传目录时会把目录内容平铺**。`phrases/` 和 `_generated/`
   必须各自指定到自己的子目录，否则它们的 ogg 会被倒进包根目录，
   还会和顶层同名文件**互相覆盖**（曾导致包内音节数从 802 变成 1618）。
2. **Cython 层的 import 静态分析看不到**。numpy 的 `bit_generator`
   在运行时 import `secrets`，必须显式写进 `hiddenimports`，
   否则打包后的程序一启动就 `ModuleNotFoundError`。
3. **窗口程序遇到未捕获异常会弹模态错误框**，自动化环境下没人点它，
   进程就永远挂着。所以 `disable_windowed_traceback=True`，
   同时入口自己 catch 住异常写进报告文件。

另外：语音包里的 `待切/` 是切音节用的原始素材（140MB，含第三方下载音频），
运行时用不到，既不进 exe 也不进 git。

## 转写规则

1. **pypinyin 上下文转写**优先，能正确处理多音字（脊椎→jǐ zhuī、只有→zhǐ yǒu、
   教育→jiào yù、重复→chóng fù）。原 `WTV.data` 只是单字表，读音经常不对
   （WTV 里 椎→zhuī 而 pypinyin 给 chuí、什→shěn）。
2. **WTV.data 作为备选读音**：主读音在语音包里没有录音时退回 WTV 的读法。
   两者谁对谁错取决于上下文（人名、生僻字），哪个有录音就用哪个。
3. **`pronunciations.json` 最终覆盖**，用于人名和生僻字。
   例：`{"椎名樱": "zhuī míng yīng"}`。

## 语音包补齐（拆 + 组合）

语音包里的单字录音只覆盖约 45% 的拼音种类。补齐思路是把音节
**拆成「F0 声调轮廓」和「频谱包络 / 段内容」，再重新组合**：

- **段内容**取自同一基础音节的已有录音（元音、声母、音色都是原声）；
- **声调轮廓**取自说话人自己对目标声调的统计模板
  （由该语音包全部录音的 F0 统计得出，形状符合普通话规范：1 平、2 升、3 降升、4 降）。

### 两种后端

| 后端 | 原理 | 音色(MCD) | 声调判定 |
|---|---|---|---|
| **声码器**（默认） | WORLD 保留频谱包络，只改基频 | 变调额外代价 **+1~4dB** | **77.8%** |
| PSOLA（兜底） | 时域基频同步叠加，段内容取自原音 | 变调额外代价 +10~40dB | 50% |

声码器完胜的原因：**频谱包络（共振峰 = 音色）原样保留**，
不会有相位抵消；而 PSOLA 一改投放速率，段内容就和投放失配 → 抵消 → "电音"。

这版 pyworld 的 d4c 有个缺陷：**约 15% 的频点是 NaN**。
处理办法（`voice_synth/vocoder.py`）：
- 清音帧 ap = 1.0（纯噪声）
- 浊音帧 ap 里的 NaN 频点在**频率轴**上线性插值补齐（ap 沿频率是平滑的）

### 标尺（看数字前先看这个）

用 MCD（mel 倒谱失真，只比声道包络，对变调引起的谐波位移不敏感）：

```
x vs x             =  0.00 dB
x vs x*0.5         =  0.00 dB   （对电平不变：音色不是"多响"）
hāo vs māo         = 85.76 dB   <- 同语音包不同音节的自然差距
补齐音节 vs 源录音 = 40.62 dB（中位）  <- 远低于"不同音节"的差距
```

> 踩坑提醒：音色距离必须**对电平不变**且**限定语音频带(0–8kHz)**。
> 源音频与合成音频的峰值因数不同，直接比绝对电平会把响度差误判成音色漂移
> （实测误判达 13dB）；而 8kHz 以上素材常是数值零，一比就放大成几十 dB 假差异。

### PSOLA 实现里踩过的坑

都写在 `voice_synth/psola.py` 的文件头，避免改回去：

1. 目标标记不能独立由 F0 积分生成再按时间就近匹配 —— 要在**周期序号**空间里
   对齐，否则相位错位，叠加互相抵消。
2. 源段**不要**逐段重采样到目标周期：目标周期一抖，重采样比例跟着抖，
   共振峰跟着抖（长时平均谱差 5.3 dB → 20.4 dB）。音高由"投放密度"决定。
3. 源标记必须**每个周期一个**，且源→目标的对应用周期序号（14/14 可跟踪），
   不要用索引比例（13/14，且谱差 7.2 dB）。
4. 源段长度 = 2 个源周期（投放间隔是 1 个周期，正好 50% 重叠，Hanning 窗求和为 1）。

> 现在 PSOLA 只是兜底路径（声码器不可用时）。它的问题不是实现细节，
> 而是原理性的：改投放速率必然让段内容与投放失配。

### 覆盖率

| | 拼音种类 | 字符加权 |
|---|---|---|
| 原包 | 45% | 62.8% |
| + 声调重组（含轻声派生） | 76% | 95.9% |
| + 音素级移植（默认开启） | 88% | **99.9%** |

构建时做**写盘后回读校验**：判据是"音色有没有被毁"（MCD / 长时谱的形状距离），
不是"F0 能不能被提取"——目标轮廓有时会让 harvest 提不出基频，
但那种情况下音色其实保住了，用 F0 可检测性去卡会误杀。

## 音素级移植层（默认开启，可回滚）

声调重组救不了"整个基础音节在包里都不存在"的拼音（neng / ran / tuan / gei / zěn…）。
这一层用**声母 + 韵母**拼出来：从包里找一个同韵母的音节取韵母，
找一个同声母的音节取声母，拼起来再换基频。

```bash
python tools/build_phoneme.py hanser     # 生成这一层
```

**怎么回滚**（这一层是完全隔离的，三种方式都行）：

| 方式 | 做法 |
|---|---|
| 界面开关 | 取消勾选"音素级补齐" |
| 环境变量 | 设 `READINGWBW_USE_PHONEME=0` |
| 彻底移除 | 删掉 `_generated_phoneme/` 和 `assets_phoneme.json` |

（默认是开的；体检项「音素级补齐」会同时验证"默认开着"和"关掉能干净回落到 95.9%"。）

产出与现有层**完全隔离**（独立目录 + 独立清单），关掉开关后行为与之前逐位一致
（`tools/phoneme_toggle.py` 会验证这一点）。

**质量门槛**：合成结果与"韵母 donor"的 MCD，必须不超过
"两个真实音节（韵母相同、声母不同）"的 1.3 倍 —— 即达到真人换一个声母的水平。
不达标直接放弃，不产出坏音频。

实测 228 个补齐成功、60 个放弃（放弃的几乎都是 cal / ceok / dim / dug 这类
外来拟声词，本来就不该用汉语音节去拼）。

### 拼接点怎么定（踩过的坑）

- **不能用 F0 找元音起点**：harvest 对塞音的闭塞段也报 F0，很多音节的
  F0 从第 0 帧就是正的，起点会被算成 0，声母段切出来是空的。改用**能量包络**
  的最大上升沿。
- **交叉淡化必须自适应**：声母段常常只有 10~20ms，固定 10ms 的淡化会把
  塞音的爆破音整个吃掉，结果里就没有这个声母了。改成不超过较短段的 30%。

## 播放链路上踩过的三个坑

这三个都不会抛任何异常，只会让声音变怪，所以专门加了对应的体检项。

1. **位深错位**（"全损音质"）：`sf.read(dtype='float32')` 出来的是浮点样本，
   直接 `tobytes()` 塞给 `pygame.mixer.Sound(buffer=...)`，而 mixer 要的是
   16-bit PCM —— float32 字节被当成 int16 解释，采样点错位、幅度失真。
   → 体检项「播放保真」：把送进 mixer 的字节解回来逐样本比，阈值 1e-3。

2. **声道数错配**（"尖细"+"短促"）：`pygame.mixer.init(48000, -16, 1, 512)`
   明明要求单声道，设备原生是立体声时实际拿回 `(48000, -16, 2)`。
   单声道数据被当成 L/R 交替消费 → **播放速度整整翻倍** → 音调高八度 + 时长减半。
   → 体检项「播放时长」：解回来的字节折算出的时长必须和源文件一致。
   → 修复：按 `pygame.mixer.get_init()` 的【实际】声道数交织，不用请求值。

3. **重采样削高频**（"薄"、"尖细"）：语音包里 44.1k 和 48k 混着，播放器统一到 48k。
   线性插值等效于三角形低通，把 11~22kHz 削掉 3~6dB，语音的"空气感"就没了。
   → 体检项「重采样保真」：高频能量占比掉超 25% 或电平偏差超 2% 就报警。

## 语音包的采样率是混的

顶层 120 个片段是 44100Hz、679 个是 48000Hz；词组里 76 / 144 也是。
播放器统一到 48000，44.1k 的片段必须重采样。

**这里踩过一个坑**：一开始用线性插值重采样。音高和时长其实都没变
（正确重采样本来就保这两样），但线性插值等效于一个三角形低通，
把 11~22kHz 削掉 3~6dB —— 语音的"空气感"没了，听起来就"薄"、"尖细"。
实测高频能量占比被砍掉 36%~41%。

现在用**带限 sinc 插值**（多相，纯 numpy，运行时不需要 scipy），
高频能量占比能原样保住（实测掉 0~8%），电平也对齐回原值。

体检项「重采样保真」盯着这个：在 10~20k 公共带内比功率谱密度，
掉了超过 3dB 或电平偏差超过 2% 就报警（实测只掉 1.1dB）。
> 注意比法：两种采样的 Nyquist 不同（22.05k vs 24k），
> 直接比"10k 以上能量占比"不是同一把尺子，会得出偏差很大的结论。

## 已知限制

- 语音包里**整个基础音节都不存在**的（neng / ran / tuan / gei / zen / huo 等）
  无法靠声调重组得到，仍会静默，约占 4% 字符。要补这一层需要做
  声母+韵母的音素级移植（formant concatenation），是下一步的方向。
- **合成音节的声调准确率无法用客观指标可靠测量**：拿"用 F0 形状做最近质心"
  分类器去判，原包**真实录音**（声调已知）只有 41.1% 准确率，
  而合成结果是 77.8% —— 已经高于真实录音。
  孤立短音节的声调本就高度重叠，这个方法已经到测量上限，
  真实听感需要人耳判断。
- 轻声是从完整声调派生（缩短 + 衰减 + 压平），不是真人轻声。
